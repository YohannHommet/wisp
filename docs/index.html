Physical Architecture

The Path of a File: 0 Hops vs 14 Hops

Sending a file to the computer next to you shouldn't route through Virginia, Frankfurt, or a public relay server. Here is how Wisp physically differs from cloud and relay utilities.

Cloud & Relay Tools

14 External Hops

Tools like Slack, WeTransfer, AirDrop (with iCloud), or Magic-Wormhole and croc relay servers depend on intermediate internet hosts:

  • 01. Laptop Wi-Fi Adapter
  • 02. Local Router / NAT Gateway
  • 03. ISP Optical Line Terminal (OLT)
  • 04. Regional Autonomous System (BGP)
  • 05. Transatlantic / Backbone Fiber
  • 06. Public Cloud Relay Server (AWS / GCP)
  • 07. Server Storage Buffer / Transit Buffer
  • 08. Return BGP Transit Route (7 hops back)
  • 14. Destination Machine
OFFLINE CAPABLE NO
TRANSFER SPEED 10 - 25 MB/s
SERVER LOGS EXPOSED

Wisp Protocol (WSP/2)

0 External Hops

Wisp operates strictly over physical radio frequencies and local copper. Packets never leave your local broadcast domain:

  • 01. Node Alpha (Sender NIC)
  • 02. Local Wi-Fi Access Point or Ethernet Switch
  • 03. Node Beta (Receiver NIC)
✔ Zero internet egress. Disconnect the WAN cable or run in an underground lab — transfers proceed at full hardware link speed.
OFFLINE CAPABLE 100% YES
TRANSFER SPEED 114+ MB/s
SERVER LOGS ZERO
Deployment & Distribution

Ready in under three seconds.

Wisp is distributed as a single static binary with zero runtime dependencies. Install on both computers and send files immediately.

Linux & macOS (x86_64, ARM64 / Apple Silicon):

curl -fsSL https://raw.githubusercontent.com/YohannHommet/wisp/develop/scripts/install.sh | bash

Windows PowerShell (x64):

irm https://raw.githubusercontent.com/YohannHommet/wisp/develop/scripts/install.ps1 | iex

Installs into user space (~/.local/bin/wisp or %LOCALAPPDATA%\Wisp\bin\wisp.exe). Never requires root or administrator privileges. Verifies SHA-256 against SHA256SUMS before staging and replaces the binary atomically.

Download precompiled native binaries for Wisp v0.2.0:

Cryptographic Invariants

Engineered to fail closed.

Wisp enforces strict protocol guarantees audited against adversarial LAN attacks, port scans, and malicious network payloads.

01

SPAKE2 Channel Binding

Untrusted self-signed TLS 1.3 certificates are cryptographically bound to the SPAKE2 PAKE key confirmation MAC. Even an active attacker with full ARP spoofing capability on an unencrypted Wi-Fi network cannot mount a Man-in-the-Middle attack without knowing the 4-word code.

02

BLAKE3 Cryptographic Receipts

Payload integrity is verified on the fly using streaming BLAKE3 hashes. The sender only exits with success code 0 once the receiving peer has verified the digest and returned an authenticated cryptographic delivery receipt over the encrypted QUIC stream.

03

Atomic No-Clobber Persistence

Files are written into temporary hidden staging files (.wisp-*.part) and atomically committed to disk upon checksum verification. If a file with the same name exists, it is never overwritten: Wisp automatically suffixes to file (1).ext. Cancelled transfers leave zero residue.

04

100% Safe Rust Core

#![forbid(unsafe_code)] is strictly enforced across the entire workspace. All memory buffers, socket channels, and cryptographic states are protected by Rust's ownership model with zero raw pointer dereferences or unsafe memory blocks.
